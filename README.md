# Интеллектуальная система модерации текстового контента

Веб-приложение для автоматической классификации пользовательских текстовых сообщений с использованием методов машинного обучения и подхода **Human-in-the-Loop**.

- **GitHub:** https://github.com/DenFr1/content_moderator

---

## 1. Назначение системы

Система предназначена для автоматического анализа текстовых сообщений и их классификации по следующим категориям:

- **`normal`** — нормальный контент, допустимый к публикации.
- **`toxic`** — токсичный контент, содержащий оскорбления, агрессию или ненормативную лексику.
- **`ad`** — рекламный контент, включая спам и коммерческие предложения.
- **`suspicious`** — подозрительный контент, для которого уверенность модели ниже установленного порога **0.70**. Такие сообщения могут быть направлены на дополнительную ручную проверку.

---

## 2. Технологический стек

- **Backend:** Python 3.10+, FastAPI, Pydantic, SQLite3, Joblib
- **Machine Learning:** Scikit-learn, TF-IDF Vectorizer на символьных n-граммах, Logistic Regression
- **Frontend:** HTML5, CSS3, JavaScript (Native ES6+, Fetch API)
- **Deployment:** Render PaaS

## 3. Установка и запуск

### Предварительные требования

На компьютере должен быть установлен **Python 3.10 или выше**.

### Клонирование репозитория

```bash
git clone https://github.com/DenFr1/content_moderator.git
cd content_moderator
```

### Запуск приложения

Из корня проекта выполните:

```bash
uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```

После запуска приложение будет доступно по адресу:

```text
http://localhost:8000/
```

Веб-интерфейс и API работают на одном сервере.

## 4. API

### GET `/health`

Проверка состояния сервера.

Пример ответа:

```json
{
  "status": "ok"
}
```

### POST `/moderate`

Отправляет текст на модерацию.

Пример запроса:

```json
{
  "text": "Ты просто идиот, заткнись и не пиши сюда."
}
```

Пример ответа:

```json
{
  "category": "toxic",
  "predicted_label": "toxic",
  "confidence": 0.93,
  "threshold": 0.7
}
```

Параметры ответа:

- `category` — итоговая категория сообщения;
- `predicted_label` — класс, который модель определила как наиболее вероятный;
- `confidence` — вероятность наиболее вероятного класса;
- `threshold` — установленный порог уверенности модели.

Если `confidence` ниже `0.7`, итоговая категория устанавливается как `suspicious`.

### GET `/history`

Возвращает историю выполненных проверок.

Пример ответа:

```json
[
  {
    "id": 1,
    "text": "Привет, как дела?",
    "category": "normal",
    "confidence": 0.84,
    "created_at": "25.10, 12:30"
  }
]
```

## 5. Как работает модерация

1. Пользователь отправляет текст через веб-интерфейс.
2. Входной текст приводится к нижнему регистру.
3. Из текста удаляются URL-адреса и лишние пробелы.
4. Обработанный текст передаётся в обученную модель.
5. Модель определяет вероятности принадлежности текста к каждому классу.
6. Выбирается наиболее вероятный класс.
7. Если максимальная вероятность ниже порога **0.70**, сообщение получает категорию `suspicious`.
8. Результат сохраняется в базе данных SQLite.
9. Результат отображается пользователю и добавляется в историю проверок.

## 7. Примечания

- База данных SQLite создаётся автоматически при запуске приложения.
- Файл модели `model_char.joblib` должен находиться в каталоге `models`.
- Папка `frontend` должна находиться в корне проекта.
- Для локального запуска используется сервер Uvicorn.
- Онлайн-версия приложения развёрнута на Render.
- В текущем варианте проект является демонстрационным приложением и не включает авторизацию пользователей, масштабирование и полноценную промышленную систему хранения данных.
